## 4. 路网 N1～N6

| 示例 | 已执行的事实与反例 | 明确边界 |
| --- | --- | --- |
| N1 | 同层未节点化交叉拒绝；不同层保持2个分量；同端点曲线路保留4条有向弧，最小成本7；COO 的2与7累加成9 | 不根据二维交点自动补路口，不推断坡道和转向规则 |

| N4 | 预算3落在线中间，只返回3单位可达道路；非比例成本拒绝比例切分 | 可达道路不直接等价于可达地块面 |
| N5 | 网络 OD 与欧氏 OD 选择不同；不可行、零权重、不可达及最大覆盖通过 | 小规模精确枚举，返回候选列编号，真实点位仍需按 ID 交付 |
| N6 | 原图不可达，假设补一条边后成本变12；假设不获验证资格 | 连通性改善不能证明新增道路真实存在 |

network_access.py 是普通可导入范式。它检查 projected CRS、稳定道路 ID、方向枚举、有限非负成本、有效简单线、层级字段及同层内部交叉。后续免费边界检查还覆盖了自定义活动几何列。它使用精确端点；没有容差吸附引擎。

仍需任务承担的前提包括：道路是否代表真实通行、层级属性是否可信、端点是否已经正确分段、是否存在遗漏限制。动态交通、公交时刻表、复杂收费和完整转向约束留给合适的现有系统。资产没有宣称生产级通用路由能力。

### 5.2 I/O 真实写读

io_roundtrip 在同一个真实 pyogrio 后端完成 GPKG 和 OpenFileGDB 写读，检查了中文字段和值、null、字符串长 ID、超过32位的数值 ID、Point 几何、图层和 EPSG:32650。OGR 再独立打开两层。GeoTIFF 检查像元、dtype、mask、NoData、CRS 和 transform。

这些检查说明当前小样本通道可用。不同模式、版本、字段和大数据仍需对应探针。例程不把 osgeo 的能力推定为 pyogrio 能力，也不处理任意 GDB 栅格写入。现有输出目录会拒绝，避免覆盖原数据。

### 5.3 分配残差

allocation_balance 保留逐区账本和未知量。测试区 a 的 expected=10、allocated=7，残差3；另一区无接收对象，残差5；含未知分配值的区残差为null，全局残差也为null。未知分区另列，没有静默填零或删除重复分配。

CLI 还验证了字符串区号的前导零。函数没有统一 PASS，也没有把总量守恒当作空间归属证明。检查参考和 System 要求把已发现的未匹配、未分配、不可达及关键假设带入最终说明。

### 5.4 分类与图面

classify_values 使用原值 Fisher-Jenks，不静默换成对数域、分位数或另一实现。25个小样本组合与独立穷举分割的最小 SSE 对照通过。另覆盖重复最小值、常数、类数超过唯一值、零、null/非有限值和显式采样。

标签、数量和 legend_labels 使用同一套右闭区间；单值首类不会因最小断点去重而丢失。超过拟合预算明确拒绝；采样必须显式请求并记录 approximate/seed。原始整数超出 Float64 精确表示范围时拒绝静默降精度。已被上游转成浮点的数据无法由该函数恢复原精度。

choropleth.py 保留显式 breaks 和连续模式，新增 fitted method。按同一过滤行顺序使用位置颜色，避免索引错位。vector_map.py 和 choropleth.py 检查真实几何类型，面不能凭 marker 冒充点。

实际 PNG 回看确认：0和1为同类，100为另一类，缺失区单独表示；图例区间与 counts=[2,1] 一致。这是功能回归图，不能当作开放任务的专业审美评测。三个原例程及字体、比例尺、栅格、多格式能力由原回归覆盖。示例布局仍需按真实图面调整。

## 6. 阶段化执行与修复闭环

### 6.1 免费协议闭环

新增测试使用 staged_compute 的真实 prefix NPY、失败 summarize、ExecutionHistory、SDK MockTransport、local_replay、实际冻结执行和 finish_task。

协议为“固定回复查询历史→固定回复提交计划→程序执行后段→固定回复交付”。前段内容指纹保持，失败的旧输出不存在，新统计正确。同一可信计划重复请求时，把实际 Python 执行函数替换为禁止启动函数，仍能完成回读。这证明接口闭环和幂等；固定回复没有证明模型推理。

原 V8.1 的真实 QGIS 参数修复、完整重算几何对照、补丁与候选代码身份、辅助依赖失效、缓存、部分失败、跨进程锁、崩溃窗口及 SQLite 恢复继续通过。

### 6.2 真实自然修复

免费准备阶段计算100万个数、300轮变换，真实计算约3.225秒，保存8MB NPY。后段因 `meann()` 报错，之后工作副本被明确替换为未执行的实验桩。模型需要区分工作文件与真实失败快照。任务未指定必须使用历史或重放。

模型第1轮调用 execution_history，取得 e000003_00 的失败快照，然后读取实际 job 和前段信息。它创建 summarize_v2.py 与新 JSON job，用普通 run_python_script 执行一次后段。旧脚本、旧 job、快照及 NPY 保留。

独立检查得到 count=1000000、sum=853750.1566408655、mean=0.8537501566408655。math.fsum 为853750.1566408657，差约2.33e-10。前段 SHA 保持。独立重新计算数组与原 NPY 逐值一致，完整重算耗时约3.057秒。

这支持“真实模型利用历史定位旧版本，保留适用前段并继续任务”。模型没有自然选择 local_replay。这个小任务里，直接修补是合理路径，不能据此要求多加管理调用。

### 6.3 真实接口诊断

第三个 Session 的提示明确说明是工具接口诊断，要求使用 history/local_replay。模型仍自行取得执行 ID、SHA、旧快照及 job，构造计划；组织者没有提供完整计划 JSON，也没有中途修改计划。

第一次 sum_job_fix_v1 使用精确补丁修复 summ()，真实输出 sum=16，native_starts=1。第二次 sum_job_fix_v2_reuse 通过 parent_repair 继承，reused=[sum_fix]，native_starts=0，引用首次成果。

两次计划首次调用即成功，没有接口失败。这提供了真实模型能够操作契约的证据，同时保留指定工具诊断的局限。自然采用和净收益仍待更合适的昂贵任务检验。

新合成路网包含单向分段道路及独立分量，需求到设施均计接入成本。独立一维道路算术确认：

- a 选择 east，5+180+1=186米。
- b 选择 east，10+40+1=51米。
- c 已接入独立分量，但无合法设施可达。
- d 超过200米接入上限，没有合法接入。

模型读取了分析 Skill、networks、network-access，以及制图 Skill、分类代码、API 和 Gotchas。它使用了精确接入、方向和两端接入成本思想，但自行写了约400行分析脚本，没有导入 network_access 资产。不能把方法一致直接算作代码复用。

两次失败分别为脚本尚未创建就调用，以及连通分量统计的 road_id KeyError；第二次由模型编辑后成功。后续又生成较长核查代码，尚未运行及完成制图便触发保护。因此没有正式 PNG，也没有完成交付；不能以 CSV 正确判整题完成。Verification 正文没有被读取。

这次读了相关 Skills，同时仍重复编写图算法。说明“读到资产”与“采用资产并节省成本”之间仍有距离。常驻提示已经建立偏好，继续强制读取更多内容未必有益。
