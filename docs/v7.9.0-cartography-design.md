本文保留迁移前设计和当时证据。当前实现见源码与[HANDOFF](../HANDOFF.md)，验收见[唯一一次真实任务](../outputs/buffer500_map_v790_20261030_01/comparison.md)。旧Layout工具与Runtime已删除。以下“待实施”描述属于设计记录。

本轮阅读现有源码、V7.8审计及其逐轮材料、V7.9缓冲出图记录和四篇Skills教程。另用两个明确的解释器查询模块、发行版元数据及函数签名。查看了既有图片快照。没有安装依赖，没有创建Figure、执行制图脚本、运行测试或调用模型API。

文中的“源码确认”“历史实测”“本轮环境核对”“设计决定”“待验证”含义分别独立。函数签名和Skill正文均为待实施设计，不能当作现有接口使用。

## 1. 设计结论与范围

建议开展迁移。新的默认制图使用Matplotlib 3.10.8、GeoPandas 1.0.1和Rasterio 1.4.3。初版仍在现有QGIS Python进程中执行，空间分析继续使用QGIS Processing和必要的PyQGIS。绘图脚本使用Agg，不初始化QgsApplication，不导入Qt/Layout。

采用一个Agent、一套GIS执行环境、一条现有脚本执行通道。绘图直接开放Figure/Axes与相关库API。共享代码只处理环境、字体、导出和实际执行记录。地图类型、配色、构图、图组和内容取舍由Agent决定。

| 决定 | 本版边界 |
| --- | --- |
| 迁移新图件生成 | 默认地图渲染、版面与PNG/SVG/PDF由科学绘图库完成 |
| 保留QGIS分析 | 算法发现、Processing、元信息、字段及空间关系检查继续保留 |
| 退出旧制图入口 | 移除两种固定template的render_map工具及其默认注册 |
| 保持自由代码能力 | 继续run_python_script；成熟例程可复制、导入、组合和扩展 |
| 控制交付范围 | 只按用户要求交付图片和数据；执行脚本、来源及内部预览留在运行记录 |
| 调整编辑性承诺 | 交付可重跑脚本及数据；本版停止新建QGZ Print Layout、QPT和配套QML |
| 保持架构规模 | 沿用LangGraph、Session、Context、文件编辑、read_image与日志 |

“模型更熟悉Matplotlib”是待验证假设。迁移是否值得，最终取决于任务正确性、图面质量和执行成本。当前证据支持减少特定API错误的机会，尚未证明新方案必然更便宜或更美观。

## 2. 当前制图系统与证据

### 2.1 实际调用链

当前[AgentFactory](../gis_agent/application.py)同时注册通用脚本工具和旧render_map（已删除）。[System Prompt](../gis_agent/prompts/system.j2)给出两个Skill的手写索引。

```text
用户任务
  → 单Agent
  → read_file读取Cartography Skill、execution.md
  → render_map(design_path, template)
       → choropleth.py或facilities.py
       → cartography_runtime.py
       → QgsApplication / 图层样式 / QgsPrintLayout / 导出
  或 run_python_script执行自定义PyQGIS布局脚本
  → 结构化结果、预览、read_image、finish_task
```

现有旧运行时（已删除）负责字体、图层、布局、工程、样式、导出与来源登记。它有可复用价值，也包含较重的成果约定：export_layout即使没有请求qgz，也会先保存QGZ、QPT及QML。默认formats为png和qgz。

现有两个例程分别支持单个面字段的分级设色，以及区域面加设施点。create_layout默认采用横向页面、左侧主图和右侧图例，缺少自然表达任意图组的入口。代码允许扩展，但模型需要自行阅读运行时并判断扩展位置。

### 2.2 为什么没有优先使用render_map

V7.9原始记录确认：M01读取SKILL.md，M02读取execution.md，之后生成自定义脚本，整个任务没有调用render_map。它共调用run_python_script 37次、edit_file 39次、write_file 14次、read_image 6次。仅看到Skill被读取，不能据此认定其方法被采用。

可观察的设计弱点如下：

1. 工具只有choropleth/facilities两个枚举。缓冲面加原始点在几何上适用facilities，但名称和说明没有明确这个用例。
2. 使用例程需要准备brief和design两份文件。执行说明有字段介绍，缺少针对该任务的一条完整、可直接执行的示例。
3. System和Skill同时开放自定义PyQGIS布局。默认路径的优先级及复用边界不清楚。
4. 固定例程能力较窄。模型自行添加网格、数据检查面板等内容后，进入了完整自定义布局路径。

以上是源码与轨迹支持的解释候选。当前没有控制实验可以确定每项的因果贡献。更换绘图库后，同样需要解决入口、示例和能力边界问题。

## 4. 新旧技术栈的能力与取舍

| 维度 | 当前PyQGIS Layout | 新科学绘图库路线 |
| --- | --- | --- |
| 普通静态图 | 有完整GIS符号和地图项，调用链较长 | GeoPandas.plot与Matplotlib直接组合，需维护地理语义 |
| 图组和统计图 | 可以实现，跨图元和布局接口较多 | Figure、GridSpec、subplot_mosaic和统计Axes容易组合 |
| 专业地理标注 | QGIS有成熟标注引擎和表达式样式 | 需筛选标签，密集避让可用附加组件，功能存在差距 |
| 投影和空间比例 | GIS框架提供较多内置支持 | 需要明确CRS、显示变换、aspect和比例尺条件 |
| 字体与生命周期 | Qt字体、C++对象与工程状态影响执行 | Agg可退出Qt路径，仍有字体覆盖、缓存和内存管理问题 |
| 可编辑成果 | QGZ/QPT/QML可承载GIS图层和布局 | 脚本与数据可重跑；SVG/PDF提供一定图形编辑能力 |
| 部署 | 现有GIS环境已经安装，但执行需配置 | 继续复用该环境；此次迁移不会移除空间分析的QGIS依赖 |
| 成本和质量 | 已有本机失败和成功证据 | 熟悉程度及性能收益均待同条件实测 |

地图渲染从PyQGIS退出，不等同于把整个项目迁出QGIS生态。当前选择针对已经观察到的布局接口问题。未知地图仍可能需要更强的地理投影、密集标注或数据泛化能力。

## 5. 绘图能力设计

### 5.1 矢量、分类和连续色带

采用[GeoPandas 1.0.1绘图接口](https://geopandas.org/en/v1.0.1/docs/user_guide/mapping.html)。直接提供ax、column、cmap、norm、zorder和missing_kwds，允许继续调用Matplotlib Artist。

输入用文件路径和独立layer参数，例如read_file(path, layer="result")。GeoPandas不直接接收QGIS专用的“路径|layername=名称”语法。图层名来自实际枚举或算法输出。显示重投影使用to_crs；set_crs只用于有依据地补充或纠正CRS标识。

分类与色标遵循同一个数据映射：

- 类别：稳定的类别到颜色映射，图例从同一映射生成。
- 离散数值：业务阈值或经说明的分类方法，记录边界闭合规则和每类数量。连续边界可用BoundaryNorm；明确包含最大值，避免边界数据被漏画或默默截断。
- 连续数值：Normalize和实际ScalarMappable；有科学中心的差值可用TwoSlopeNorm。不同面板共享色标时共享同一norm和cmap。
- NoData：单独掩膜、颜色或纹理，零值正常进入数值映射。记录缺失与有效样本数。
- 分位数需要处理重复边界。自然断点需要已验证的分类库；当前mapclassify缺失，不能通过设置scheme就假定可用，也不临时复写Jenks算法。

显示字段、筛选和归一化由任务决定。绘图代码保留稳定ID，不用渲染顺序或DataFrame重排后的行号回指原对象。

### 5.2 栅格和矢栅混合

Rasterio负责读取、窗口、NoData、必要的显示重投影及预览抽样。分析栅格保持原状。Matplotlib负责imshow、pcolormesh、contour及图面组织。

空间对齐必须明确处理：

1. 矢量和栅格使用同一显示CRS。
2. 使用[plotting_extent](https://rasterio.readthedocs.io/en/stable/api/rasterio.plot.html)取得imshow的left/right/bottom/top。它的顺序与Rasterio bounds不同。
3. 读取out_shape后同步缩放Affine transform，避免预览像元错位。[重采样说明](https://rasterio.readthedocs.io/en/stable/topics/resampling.html)。
4. 有旋转或不同CRS的栅格，优先通过[WarpedVRT](https://rasterio.readthedocs.io/en/stable/api/rasterio.vrt.html)得到明确的显示网格；不能只套包围盒拉伸。
5. 类别数据采用保持类别的重采样方式；连续数据按任务选择插值。RGB按colorinterp、掩膜和共同拉伸条件组织。

大栅格按地图范围读取窗口，以输出像素需要确定抽样尺寸。提高DPI不会增加原始数据分辨率。显示抽样不用于回写分析统计。记录CRS、transform、band、NoData和显示重采样方法。

### 5.3 多层叠加、局部图和图组

Matplotlib中较大的zorder通常位于上方。显式控制层序，背景、全部对象、选中对象和标签分别确定。不要沿用QGIS“索引0在最上”的列表规则。

多面板直接使用Figure.subplots、GridSpec或subplot_mosaic；局部地图使用Axes.inset_axes及范围指示。地图Axes保持所需空间比例，统计Axes按统计语义设置比例。共享图例、共享色标和地图范围均由比较目的决定。[布局能力](https://matplotlib.org/stable/users/explain/axes/arranging_axes.html)、[局部图能力](https://matplotlib.org/stable/gallery/subplots_axes_and_figures/zoom_inset_axes.html)。

本轮已在Matplotlib 3.10.8读取inset_axes、indicate_inset_zoom、savefig和AnchoredSizeBar签名，没有执行它们。实施时以该版本API为准，避免复制其他版本的返回值解包方式。

Agent可以创建任意数量和形状的Axes、组合统计图、绘制等值线、流向或自定义符号。三个初始例程只展示正确用法，工具参数中不再存在地图类型枚举。

### 5.4 比例尺、指北针与标注组件

先复用已存在的Artist和组件。当前未安装的组件仅列为后续依赖候选。

| 能力 | 可复用能力 | 本版选择及条件 |
| --- | --- | --- |
| 基本比例尺 | Matplotlib内置AnchoredSizeBar | 基线使用。size为ax.transData中的长度，标签与CRS单位一致；程序不承诺自动地面距离校正 |
| 自动长度、单位和样式 | matplotlib-scalebar | 轻量可选，发行元数据仅列Matplotlib依赖。后续安装、固定版本并验证后才能使用 |
| 真北旋转、复杂比例尺、局部图 | matplotlib-map-utils 4.1.1 | 按需候选，需要Cartopy>=0.23、Pydantic>=2.13.3等。Python和Matplotlib版本下限满足，依赖当前未齐 |
| 图例和色标 | Legend、Patch/Line2D、ScalarMappable | 默认使用，数据映射与图例共用一份定义 |
| 标签避让 | annotate、path_effects；adjustText可选 | 先选择重要标签；密集场景再评估成熟避让组件 |
| 全局/极区地理轴 | Cartopy可选 | 普通本地投影图不需要。全球跨日期变更线、极区和曲线经纬网需专门验收 |

来源：[AnchoredSizeBar](https://matplotlib.org/stable/api/_as_gen/mpl_toolkits.axes_grid1.anchored_artists.AnchoredSizeBar.html)、[matplotlib-scalebar](https://github.com/ppinard/matplotlib-scalebar)、[其依赖定义](https://github.com/ppinard/matplotlib-scalebar/blob/master/pyproject.toml)、[map-utils依赖](https://github.com/moss-xyz/matplotlib-map-utils/blob/main/pyproject.toml)、[真北接口](https://moss-xyz.github.io/matplotlib-map-utils/north_arrows/)、[adjustText](https://github.com/Phlya/adjustText)。

比例尺和指北针只在任务需要时加入：

- 投影坐标的“米”也有投影尺度差异。局部合适投影的比例尺按明确近似解释；经纬度、Web Mercator或大范围地图不能直接假定坐标单位等于地面米。
- 地图上方不总是真北。标明真北或网格北及参考位置。优先使用已有CRS感知组件；依赖缺失时说明缺口，禁止猜测一个朝上的N箭头。
- 用户明确要求尚未支持的真北功能时，按缺少能力处理，不能将其悄悄删去。后续依赖准入前，这项能力保持条件性支持。
- matplotlib-map-utils文档要求在确定轴范围、页面尺寸等条件后添加元素，并提示部分API可能调整。启用前需固定版本，分别验证预览与正式输出。

基线不同时引入多个比例尺封装，也不自行编写完整的地图装饰库。

### 5.5 中文字体、物理尺寸和导出

保留现有字体路径配置和字体文件指纹。替换Qt注册方式，使用font_manager.fontManager.addfont及明确FontProperties。字体注册需在新进程中执行。缺字与字体回退需要保留可观察信息。[Matplotlib 3.10.8字体API](https://matplotlib.org/3.10.8/api/font_manager_api.html)。

字号用pt，画布用inch；毫米尺寸除以25.4。点符号markersize/s通常表示pt²，不能直接照搬QGIS的毫米直径或把数值平方两次。线宽同样需要明确单位。保留少量字体层级，最终尺寸下检查图例和标签。

正式输出通过[Figure.savefig](https://matplotlib.org/3.10.8/api/_as_gen/matplotlib.figure.Figure.savefig.html)支持PNG、SVG和PDF：

- 默认只生成任务要求的正式格式。PNG以约定物理尺寸和DPI输出；预览控制为长边约1600～1800像素，并满足read_image限制。
- 有正式PNG时，预览从同一成品等比例缩小。只有SVG/PDF时生成一份内部PNG预览。避免为同一版面重建数据、重跑分析或生成多份风格试稿。
- 固定物理尺寸或数字比例尺要求下，谨慎使用bbox_inches="tight"。裁剪会改变页面边界；声明的1:n应根据最终地图Axes的实际物理宽度重新核对。
- 屏幕缩放和打印缩放会改变数字比例。一般优先提供随图片缩放的图形比例尺。
- SVG可选择保留text；查看环境需具备相应字体。PDF可配置TrueType嵌入。字体合规性和可编辑性需要检查实际文件，不能只凭扩展名断言。
- 大量几何或密集网格可按Artist选择rasterized，减少SVG/PDF体积。文字和必要边界可保留矢量。栅格部分仍受DPI限制。[官方栅格化说明](https://matplotlib.org/stable/gallery/misc/rasterization_demo.html)。

默认图面不展示脚本版本、顶点数、检查日志、整段CRS说明和验证报告。必要的单位、时间、来源和方法简注按任务加入。详细技术信息进入运行结果或图注文件。

## 6. 执行架构与接口

### 6.1 唯一脚本执行入口

继续使用现有模型工具：

```text
run_python_script(script_path, arguments=None)
  → 已配置QGIS Python启动器
  → Agg绘图脚本
  → 可组合的Matplotlib / GeoPandas / Rasterio API
  → export_figure
  → result.json、预览和正式图件
```

保持该模型工具的名称和参数。移除旧render_map注册，避免两个含义接近的执行入口。Agent既可以复制成熟例程，也可以直接编写plot.py调用相同辅助函数。

绘图库只在外部GIS解释器中导入。application和Agent进程不导入新的绘图运行时，否则当前Conda环境会立即出现缺包错误。

runner保留真实退出码、脚本快照、文件变更检测、完整stdout/stderr及结构化结果文件。设置MPLBACKEND=Agg、UTF-8及现有字体环境变量。共享代码的模块根路径由程序提供，避免模型推断工作目录；脚本当前工作目录仍为自身目录。

Windows批处理参数问题必须先修。建议将用户参数保存到本次执行的JSON请求文件，通过小型Python启动脚本还原sys.argv后运行目标脚本。避免把图层URI等载荷交给cmd解释。该修复需同步核对所有run_python_script调用方；不得只对本次buffer文件名打补丁。

### 6.2 最小Python辅助接口

新增gis_agent/integrations/plotting/runtime.py。计划仅提供字体环境和成果导出两组职责：

```python
configure_plotting(font_files=None) -> dict

export_figure(
    figure,
    output_dir,
    *,
    formats=("png",),
    dpi=300,
    inputs=(),
    map_panels=(),
) -> dict
```

configure_plotting只设置Agg、显式字体和必要的导出选项，不选择颜色、画布布局或地图类型。函数返回实际字体信息。字体路径优先沿用GIS_AGENT_FONT_FILES。

map_panels用小型dataclass表达名称、Axes和声明的CRS；统计Axes不用注册为地图。export_figure从实际Figure/Axes读取页面尺寸、最终范围、aspect和图元概况，写正式输出、预览和manifest，再写GIS_AGENT_RESULT_PATH。inputs记录实际数据文件依赖；Shapefile旁文件和目录型数据沿用现有指纹规则。

这些信息用于观察与追溯。运行时无法仅靠Axes推断某个Artist是否经过正确重投影，也无法证明模型声明的CRS真实可靠。空间核查仍需输入数据和实际转换证据。

首版不包裹GeoPandas.plot、颜色归一化和subplot_mosaic等常用API。栅格窗口/transform处理先放进完整例程；多次复用后再提取小函数。没有收益证据时不创建RenderEngine类、渲染DSL或插件注册中心。

### 6.3 结果约定

沿用执行器顶层ok、returncode、日志路径、脚本与结果哈希。绘图结果放在现有result中，示意如下：

```json
{
  "ok": true,
  "returncode": 0,
  "result": {
    "version": 2,
    "ok": true,
    "files": {"png": "<绝对路径>/map.png"},
    "preview": "<绝对路径>/preview.png",
    "manifest": "<绝对路径>/manifest.json",
    "artifacts": ["<绝对路径>/map.png"],
    "figure": {"width_mm": 180, "height_mm": 140, "dpi": 300},
    "map_panels": [{"name": "main", "crs": "EPSG:32650", "extent": [0, 0, 1, 1]}],
    "warnings": []
  }
}
```

数值仅用于解释结构，实际结果全部由执行代码生成。长版来源、图元与环境记录写manifest，工具只返回短摘要和路径。程序不要求Agent手填哈希、文件长度或内部证据编号。

失败脚本产生的图片保留为诊断文件。非零退出、无效结果或result.ok=false不能因图片存在而变成成功。PNG存在也不能证明所有图层可见。

旧maps.layers_top_first不直接沿用为新层序字段。新清单可以记录实际Artist zorder及输入来源，避免混淆两种引擎的层序语义。

现有render_map缓存绑定固定例程和明确设计依赖。开放plot.py无法完整推断文件、随机状态和外部数据依赖。首版保留指纹与已存在成果引用，停止自动复用任意脚本的渲染结果。未来只有在声明依赖和实测收益充分时才扩展缓存，不做透明猜测。

| R01 数据编码 | 比率/密度可面填色，总量考虑比例符号，类别保持离散色义 | column、markersize、categorical | 字段、分母和单位；符号面积对应量 |
| R02 分类 | 业务阈值优先，统计分类按分布和读图目的选择 | boundaries、norm、每类数量 | 临界值、最大值、空类、重复边界 |
| R03 色彩与缺失 | 顺序、发散或类别编码分别处理，NoData独立 | cmap、Normalize、TwoSlopeNorm、missing_kwds | 中心有依据，零值与缺失可分 |
| R04 图底关系 | 背景支持定位，主题承载主要对比 | zorder、alpha、linewidth | 主题未被背景或全部对象盖住 |
| R05 点符号 | 根据任务控制大小和密集点表达 | markersize/s、edgecolor、局部图 | 点数量、定位及小区域遮挡 |
| R06 标注 | 优先必需名称，按尺度和信息重要性筛选 | annotate、fontsize、path_effects | 必需标签、碰撞和裁切 |
| R07 图例 | 从同一编码定义产生，按阅读顺序排列 | handles、ScalarMappable、cax | 色义、边界、单位和NoData一致 |
| R08 版式 | 主图占据符合任务的主要空间，按地理范围选纵横比 | figsize、GridSpec、layout | 缩至实际使用尺寸后仍可读 |
| R09 局部图 | 主图不能同时保留全局与必要细节时使用 | inset_axes、extent、范围指示 | 局部位置真实、独立比例明确 |
| R10 可比性 | 同区域多时相或产品比较 | 共享CRS、范围、norm、图例 | 差异来自数据，独立拉伸已说明 |

这些规则不规定固定配色、固定比例尺长度或必须的右侧说明栏。案例主要解释设计取舍，避免用外观相似代替数据语义核对。

### 8.7 完整示例需要覆盖什么

| 示例 | 最低完整内容 | 可自由变化的部分 |
| --- | --- | --- |
| vector_map.py | 读取真实GPKG层、统一CRS、点面zorder、合适范围、按需比例尺、中文标题、导出 | 图形符号、配色、版式、任何新增图层 |
| choropleth.py | 真实数值字段、连续/离散两种写法、缺失值、分类计数、共用编码的图例 | 分类方法、颜色、面板和标注 |
| raster_composite.py | masked读取、窗口/抽样transform、矢量对齐、主图/局部/统计Axes组合 | 栅格波段、地图数量、图组形状、统计表达 |

例程中的路径和数据选择集中在顶部小配置中。它们必须在实施阶段用真实数据验证后才能标记为“已验证”。本设计不提供未经执行的长脚本并宣称可以直接使用。

references/api.md给出本机版本的常用签名、最小调用、返回值和来源；不重写Python基础课程。分析用Processing初始化移到共享qgis/execution.md，制图Skill只解释本版绘图环境。

### 8.8 Gotchas初稿

优先积累以下高价值内容：

- QGIS Python和Agent Conda的包位置不同；绘图模块只能在配置的GIS进程中加载。
- 工作目录是脚本目录，导入项目助手应使用程序提供的根路径。
- GeoPandas layer为独立参数；QGIS URI要在接口边界转换，避免批处理竖线。
- zorder方向与QGIS图层列表索引不同；面默认填色也可能盖住点线。
- facecolor="none"与Python None含义不同；边界绘制可明确用boundary.plot。
- GeoPandas的scheme依赖mapclassify；缺包时不能靠猜参数修好。
- NumPy数组下采样后transform也要更新；旋转栅格不能直接塞进普通extent。
- 字体文件存在不证明完整字符覆盖；每个新进程都要注册字体，不能无声回退后宣布成功。
- 地理坐标和地面米不能直接互换；EPSG:3857的米也需要尺度判断。
- pyplot状态和多个Figure可能导致保存错图；显式使用fig/ax并close对应Figure。
- 保存成功、manifest完整和工具ok分别证明有限性质；图面仍需查看。
- 正常近似、字体可移植性等已知限制可写summary；unresolved用于仍未完成的要求，避免重复拒绝completed。

## 9. 图像反馈与成果验证

### 9.1 三种检查分开

| 层面 | 取得的证据 | 不能单独证明的内容 |
| --- | --- | --- |
| 执行与文件 | 退出码、文件可解析、尺寸、哈希、实际导出格式 | 数据语义与所有对象可见 |
| 空间与编码 | 输入CRS、显示变换、有效范围、分类计数、单位、实际叠加样本 | 人类能否快速读懂 |
| 图面与阅读 | 当前整图、局部细节、读者回答任务的表现 | 全量空间关系和统计公式正确 |

空间检查复用现有inspect_data、summarize_fields和check_spatial_relation。必要时补少量独立样本计算，沿用已核查分析事实。不能让制图重复完整分析，也不能以图面正常推断分析已正确。

### 9.2 看图的具体方法

先看当前整图，检查主要地理对象、范围、编码、标题/图例和必要元素。只有怀疑局部问题时再crop。read_image仍仅在紧接的一次模型请求携带图片；改图后需要看更新版本。

修正优先级如下：

1. 数据、CRS、错位、方向或编码有误。
2. 必需图层被遮挡，关键点/面/标签缺失。
3. 图例错误、文字裁切、必要内容难以阅读。
4. 对读图有明确帮助的层级和间距修正。

每次只需简短表达具体缺陷、位置、原因和修改结果。可在一个edit_file调用中替换一段相关代码，不把同一处修复拆成多轮单行编辑。图像正确且需求完成时结束，不通过持续改变色相、边框和装饰来证明认真工作。

这里使用按缺陷驱动的停止条件。没有固定两次修图规则。重复出现同一种错误且没有新证据时，优先读Gotchas/API或回到成熟例程，避免继续猜接口。

当前read_image限制为8MiB、边长8192、1600万像素，仅支持静态PNG/JPEG/WebP。正式高分辨率PNG超限时保留原文件，用对应预览和必要裁剪检查。SVG/PDF通过同一Figure的预览及后续格式检查取得证据，不伪造工具支持。

### 9.3 空间表达的最低检查点

- 矢量：实际层、数量、有效CRS和显示范围正确；预期对象没有因过滤或缺失值处理消失。
- 栅格：已知锚点或边界与矢量对应，transform和NoData正确，显示抽样未污染分析。
- 分类：所有有效值恰好进入应属类别，边界与图例一致；NoData和零值保持区别。
- 比例尺与真北：有适用的CRS、单位和参考位置；实际画布改变后仍正确。
- 比较图：共享条件保持一致，变化原因可以解释。

导出助手可提示非有限轴范围、空地图图元和明显出界文本。这些只能作为错误线索。任意版面中的全面遮挡、审美和阅读成本仍需视觉与人工判断，首版不实现全能视觉评分器。

## 10. QGZ交付与插件展示

本版不生成新的QGIS Print Layout、QPT或配套制图QML，也不承诺将Matplotlib Figure转换成原生可编辑QGIS布局。

新的可重现交付为“输入/分析数据 + 绘图脚本 + 环境和来源记录 + 图片”。SVG/PDF可能支持图形或文字编辑，但缺少QGIS图层、样式表达式和布局对象语义。PNG是像素图。将PNG放入QGIS工程只会得到图片展示能力。

已有QGZ/QPT/QML继续作为历史产物保存。既有QGIS样式里的简单颜色、边界和分类可以人工迁移到Python绘图参数，复杂表达式、比例依赖样式和布局没有通用无损转换承诺。遇到用户明确要求新QGZ布局时，说明本版交付边界，不静默改格式。

未来QGIS插件仍可加载GPKG/GeoTIFF、控制图层显示和展示分析成果。这属于插件与当前工程的接入能力。专题图排版和静态导出继续由科学绘图层完成。此次不实现插件、桌面应用或云端部署。

## 11. 分阶段实施步骤

### 阶段一：先打通最小执行与字体

1. 冻结当前源码、提示、环境和历史结果指纹；不覆盖历史输出。
2. 完成GIS环境读写兼容性验收。修复JSON参数传递，继续统一解释器。

### 阶段二：迁移方法、资源和调用方

1. 完成三个小型完整例程及四份按需参考。将规则中的PyQGIS参数替换为新API对应项。

### 阶段三：验证与小规模真实评测

先运行与变更对应的离线真实文件检查，再在用户授权后运行下一节的模型任务。发生回归时按模块修复，不借迁移扩大到模型路由、Memory或新Agent架构。

普通矢量和栅格路径稳定后，再根据真北、自然断点和密集标注任务决定可选组件准入。记录版本、依赖和实际收益。发布前整理统一受控GIS运行环境及字体资源来源。

## 12. 后续验证与评测计划

### 12.1 三个真实任务族

| 任务 | 固定条件 | 硬性检查 | 图面检查 |
| --- | --- | --- | --- |
| 简单缓冲图 | 原始point数据SHA不变，EPSG:32650，500m，SEGMENTS=32；要求PNG和数据 | ID、有效几何、范围、分段精度；原始数据不变 | 点面均可见，图例与单位正确，必要文字可读，无大块技术报告 |
| 分级设色图 | 固定带零值、NoData、极值和临界值的面数据；明确字段语义 | 类别成员/计数、边界、NoData和色标一致 | 明确层级、图例可靠、缩至约定尺寸后可读 |
| 复杂多图层图 | 固定栅格、面、路网、设施和选中对象；需要局部图与统计面板 | 显示CRS、栅格锚点、单位、筛选、共享比较条件 | 主次清楚、主题可见、局部范围对应、图组不拥挤 |

第一个任务保留原始几何精度，正式交付不附加QGZ。第三个任务保留必要复杂度，不能删掉要求后宣称更省钱。任务数据与评分标准先固定，评分答案不进入Agent上下文。

### 12.2 先分离绘图和完整任务

绘图能力比较先使用相同的已核查分析成果，避免把分析错误算作绘图错误。随后再跑“读取数据→分析→出图→交付”的完整小任务，观察制图是否引起重复分析和上下文膨胀。

离线检查使用真实文件和真实库，覆盖已发生或确实可能出现的失败：多图层GPKG、URI参数、NoData/零、重投影、旋转栅格、缺字体、错误字段、空范围、错误结果JSON和非零退出。按模块选取必要项，不建设庞大的覆盖率测试工程。

### 12.3 低成本对照顺序

| 条件 | 引擎与方法 | 可以回答的问题 |
| --- | --- | --- |
| A | PyQGIS旧路线，统一PNG需求 | 同交付范围的当前基线 |
| B | Matplotlib路线，仅给最小API与执行说明 | 更换引擎后的基础差异 |
| C | B加新Skill和成熟助手/例程 | 方法与复用的合并收益 |
| D | C加按缺陷驱动的视觉反馈 | 视觉反馈的增量收益 |

首次每任务每条件只做一次诊断性运行；稳定后至少重复三次并保存失败运行。单次结果不支持稳定性结论。固定模型版本、参数、记忆开关、数据、提示、可交付格式和预算。缓存热度无法保证一致，必须分别报告hit/miss。

C同时改变知识和可复用代码，不能把收益全部归给Skill文本。确需进一步归因时，再增加“仅助手”“仅参考案例”等小消融。当前不预先展开完整组合实验。

Skill触发另设少量短题：明确要求地图、换一种说法要求空间可视化、要求修改已有图件，以及只输出缓冲数据、只查询CRS两个相邻负例。检查误触发和漏触发，随后检查实际执行是否受益。不把所有任务调用同一个例程作为评分目标；简短、正确的自由绘图代码同样可以通过。

A的默认实现会附带保存工程，属于其真实内部成本；报告须标明。若要单独测引擎开销，再准备去掉额外交付的PyQGIS实验分支并记录该控制改动。V7.9的0.586161元只作历史问题证据，不直接充当同条件A。

### 12.4 评测指标

| 维度 | 记录方式 |
| --- | --- |
| 任务完成率 | 必需图件、格式、数据与要求是否全部完成；失败和超预算均保留 |
| 空间与编码正确性 | 独立检查输入、投影、对齐、类别、单位和必要样本；错误不能被美观分抵消 |
| 图件质量 | 隐去引擎标签后，由人按信息重点、编码、层级、文字、空间利用评分；记录具体缺陷 |
| 阅读成本 | 对指定问题记录回答正确率、定位关键区域所需时间和误读 |
| 工具错误 | 调用数、失败数、错误类型、恢复成功率及重复错误 |
| Agent行为 | Skill是否触发、实际读取了什么、是否复用代码、是否重复分析、无关修图次数 |
| 模型成本 | 响应次数、输入hit/miss、输出及思考token、图像请求；按当次价格估算并核对账单 |
| 执行开销 | 冷/热启动、数据读取、绘制、导出、总时长和大数据峰值内存 |

图面评分采用简短1～5级量表，并给出可见依据。有条件时由两名独立观察者盲评。模型可辅助描述，但不把同一个模型的自评作为唯一通过依据。

质量门槛先于成本：空间表达和必需内容通过，再比较费用中位数、范围和尾部失败。简单任务0.1元继续作为探索目标；“缓冲加图”的预算在新测试开始前另行固定。评测监督预算用于识别失控运行，不进入产品的固定修图次数规则。

## 13. 最有力的反对意见与替代方案

| 反对意见 | 判断与应对 | 替代方案 |
| --- | --- | --- |
| 现成QGIS例程已能出图，换库可能绕远 | 成立。未采用例程与引擎缺陷要分开，先在对照中保留稳定QGIS路径 | 只改善Skill及例程选择，继续PyQGIS；作为对照或回退候选 |
| Matplotlib同样可能生成大量错误代码 | 成立。需要成熟初始化/导出、小例程和局部编辑，保留真实错误 | 先缩小到常见静态图，逐步验证复杂能力 |
| 专业标注和复杂地理投影能力可能下降 | 是实质能力差距，基础三库不能自动补齐 | 经依赖验收增加Cartopy、map-utils或标签组件；无法满足时说明缺口 |
| 简单示例会造成地图同质化 | 若入口只有枚举模板就会发生；开放Figure/Axes和任意脚本组合 | 例程提供正确操作，Agent按数据与任务决定构图 |
| 依赖管理会重新复杂化 | 当前用户级安装及不同GDAL版本已经显示此风险 | 固定统一GIS环境，按需引入组件，数据链验收后再发布 |
| 可编辑QGIS工程能力损失 | 确实损失，脚本重跑和SVG编辑无法覆盖全部GIS工程语义 | 保留旧成果；用户有明确工程需求时单独评估该能力 |
| 图更美却表达错误 | 迁移不会修复公式、ID和空间归属 | 保留分析核查，空间/编码门槛单独判定 |
| 减少读图会错过真实缺陷 | 盲目压轮数有风险 | 保留当前整图及必要局部反馈，按影响理解的缺陷决定是否继续 |
| 一次低费用运行就全面宣布成功 | 样本不足，缓存和自主参数会干扰结论 | 同条件重复、独立评分、保留全部失败记录 |

推荐先完成基础迁移与共同交付范围的小评测。若新路线的正确性或图件质量明显下降，暂停扩大迁移范围，依据失败类型选择补足能力或采用替代方案。不能仅靠删掉要求、降低几何精度或减少必要核查达成低成本。
