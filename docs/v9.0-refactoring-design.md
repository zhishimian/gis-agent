## 1. 范围界定与收缩决定

为确保 V9.0 每一项改动干净、可验证、零虚胖，严格收缩本阶段边界：

- **纳入 V9.0 实施范围**：
  1. **静态工具协议与可靠执行器（Slice 1）**：取消动态增删 `qgis_*` 工具 Schema，改为静态 `search_qgis_tools` + 带完整参数校验的 `run_qgis_algorithm`；归档零调用的 `local_replay` 重锁；补齐 Windows 写锁退避重试、子进程树超时强杀、源头头尾日志截断、显式结果优先 + 递归增量文件回执、文件工具写边界与 `finish_task` 非空产物校验。
  2. **快速数据探针升级（Slice 2）**：升级 `inspect_data` 优先走 `pyogrio / rasterio` 头信息与 `256×256` 概览窗口抽样（保留 `PyQGIS` 多图层容器回退），补齐栅格 `dtype`、`colorinterp`、`units`、`scales/offsets` 与矢量坐标轴单位/几何有效性抽检。
  3. **`uv` 环境统一与三端解耦内核（Slice 3）**：建立 `pyproject.toml` 与 `uv.lock`；将核心运行循环解耦为不强绑 `langgraph` 与 `tokenizers` 的显式状态循环 + `sqlite3` 权威状态存储；支持独立空间 Python 与可选 QGIS 双后端，划清 `core / runtime / tools / adapters` 单向依赖骨架（对齐大厂 Agent Infra 标准分层：Harness Kernel、Managed Runtime、Context/Memory、Tool/MCP/Sandbox、Trace/Evaluation）。
  4. **探索性消融与对照验证（Slice 4，收费前单独确认）**：在固定旧基线（`d541c8a`）同模型同数据条件下对比代表性长程任务。
- **明确移出 V9.0（保持现状不折腾）**：
  - **暂不改动制图子系统**：保留现有 `integrations/plotting/runtime.py` 与 `gis-cartography` Skill 原样稳定运行，不在本轮额外堆砌制图零件库或新渲染规则。
  - **暂不开发 GUI / 可视化画布前端**：桌面端与 QGIS 插件界面延后至 V9.1+，本轮仅预留 `EventSink` 事件接口与适配器桩位。

## 2. 实施前执行契约（修正关键边界条件）

1. **SQLite 检查点与 Session JSON 的一致性权威规则**：
   - **SQLite 检查点为执行推进状态的唯一权威源**；`SessionStore` JSON 为追加式完整消息与资产事实记录。
   - **崩溃窗口对账规则**：进入工具执行前，先在 SQLite 记录 `pending_call(call_id, tool_name, side_effect=bool, status="started")`；工具返回并写入 `Session` 消息后，再将 SQLite 更新为 `"finished"` 并同步 `record_hash`。
   - 若崩溃发生在 `Session` 已追加完整工具结果但 SQLite 尚未更新的窄窗口，恢复时校验消息单元完整且 `call_id` 匹配后向前对齐 SQLite，不报错锁死；若崩溃发生在外部副作用工具 `"started"` 期间且无完成结果，生成确定性 `status="interrupted"` 工具消息（禁止自动重放），交由模型检查现场文件决定后续动作。
2. **文件写入权限边界的诚实定义**：
   - **Agent 文件工具（`write_file` / `edit_file`）与 `run_qgis_algorithm`**：在工具层强制校验目标路径位于允许的工作区/输出目录内，且禁止覆盖登记的原始输入路径（`protected_paths`）。
   - **自由 Python 脚本（`run_python_script`）**：明确定位为**受信任的本地隔离目录执行**（非操作系统内核级沙箱）；通过运行前后校验已登记原始输入的元数据/指纹做篡改告警，不在文档中夸大为绝对沙箱隔离。
3. **产物发现优先级与递归扫描**：
   - 优先读取脚本写入 `GIS_AGENT_RESULT_PATH` 的显式结果并校验其引用文件真实存在；
   - 辅助增量回执采用**受限深度递归遍历（`os.walk`，跳过 `__pycache__`、`python_logs`、`.git`，上限最多枚举 `5000` 项）**对比运行前后 `(mtime_ns, size)` 变化，确保 `outputs/stage1/sub/clean.gpkg` 等嵌套子目录产物不漏报，且不读取文件内容以免阻塞大栅格 I/O。
4. **纯 Python 最小核心与可选依赖严格分层**：
   - `gis_agent.core` 仅依赖 Python 标准库（`json`, `sqlite3`, `hashlib`, `dataclasses`, `pathlib`, `time`）；
   - `Pillow` 仅在启用视觉工具 `tools/images.py` 时按需延迟导入；`httpx` / `openai`、`jinja2`、`typer` 及 `geo` 科学计算包分别归属对应集成与可选依赖组，不在 `core` 顶层硬导入。
   - 必须在本机 Windows 环境实际跑通 `uv lock` 与 `uv sync` 验证无版本冲突。
5. **`finish_task` 完成核查与 QGIS 通用入口边界**：
   - `finish_task(completed)`：① 若创建了计划则要求 `plan.unfinished()` 为空；② 所提交的 `artifacts` 必须为绝对路径、真实存在且非 `0` 字节空文件；③ 返回结果附带当前会话输出目录实际文件清单摘要，辅助核对是否遗漏用户要求的文件，无指定文件要求时允许开放式完成。
   - `run_qgis_algorithm`：通过 `qgis_process --json run <id> -` 标准输入 JSON 传参；区分必填输出与可选输出（可选输出未传时不强制报错），支持 `project_path` 顶层工程上下文。
6. **Token 估算与动态水位**：
   - 压缩高水位不写死绝对常数，按 `min(configured_high_water, model.context_window - model.max_tokens - safety_margin)` 动态计算；字符系数仅在尚未获得本轮 API 真实 `usage.prompt_tokens` 的增量尾部作保守上界近似。

## 3. 模块分层结构与清理范围

```text
E:/vscode/gis-agent/
├── pyproject.toml              # uv 项目与分层依赖声明 (core / cli / geo / mcp / dev)
├── uv.lock                     # 经本机实测解析锁定的依赖树
├── gis_agent/
│   ├── core/                   # 纯标准库可导入内核：loop.py, context.py, planning.py, memory.py, events.py, model.py
│   ├── runtime/                # 执行控制与快检：runner.py, probe.py, inspect_fast.py
│   ├── persistence/            # 存储层：json.py(含写锁退避), sessions.py, checkpoints.py(sqlite3), images.py, executions.py
│   ├── integrations/           # 外部桥接：llm.py, qgis/(catalog, adapter, client, execution.md), plotting/(保持现状)
│   ├── tools/                  # 静态工具集：files.py, qgis_python.py, qgis_alg.py, planning.py, images.py, registry.py
│   ├── skills/                 # 现有三大 Skills（保持制图稳定，仅同步静态 QGIS 工具调用说明）
│   └── adapters/               # 交付入口：cli.py(原cli迁入并保留兼容导出), harness_mcp.py, stubs
└── archive/v8_replay/          # 归档移出活动路径的 V8.1 replay.py / repairs.py 等模块（git mv 保留历史）
```

## 4. 实施切片与离线验收顺序

1. **Slice 1（执行安全、静态工具协议与 V8 重放归档）**
   - 实施 `persistence/json.py` 退避重试、`runtime/runner.py`（超时树清理 + 源头截断 + 递归文件增量回执 + 输入指纹核对）、静态 `search_qgis_tools` + `run_qgis_algorithm`、移除默认 `local_replay` 并保证 `schemas` 跨轮恒定、增强 `finish_task` 非 `0` 字节检查。
   - 验收：新增针对性单测 + 现有离线回归测试通过。
2. **Slice 2（快速头信息与概览数据探针）**
   - 实施 `runtime/inspect_fast.py` 并接入 `inspect_data`，补齐栅格波段物理元数据与概览抽样、矢量单位与几何快速抽检。
   - 验收：覆盖 Byte RGB 图、未缩放 DN 图、多图层 GPKG、缺 CRS 数据的离线测试全部通过。
3. **Slice 3（`uv` 环境落地、纯 Python `core/loop.py` 与三端适配器骨架）**
   - 落地 `pyproject.toml` 并实测 `uv sync`；用 `core/loop.py` + `persistence/checkpoints.py`（`sqlite3`）替换 `LangGraph` 运行时包装，移除 `tokenizers` 强依赖；支持独立 GeoPython 与可选 QGIS 双后端配置；建立 `adapters/` 骨架。
   - 验收：全套离线回归（含 30+ 轮长循环、中断恢复不重放副作用、等待续跑 `needs_input`、上下文压缩）100% 通过，且最小纯标准库环境可成功导入 `gis_agent.core`。
4. **Slice 4（探索性消融准备与交接更新）**
   - 更新 `HANDOFF.md` 与基准运行器配置支持 V9.0 环境；待用户确认预算后再启动真实 API 探索性对照。
