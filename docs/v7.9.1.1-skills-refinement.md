## 2. 官方方法的具体落实

本轮核对了四篇原文的相关章节：

- [OpenAI：Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：description围绕真实任务，根文件提供条件化资源入口；不增加固定调用路线，也不将模型升级经验直接外推到DeepSeek。
- [Anthropic：Complete Guide](https://resources.anthropic.com/hubfs/The-Complete-Guide-to-Building-Skill-for-Claude.pdf)：先固定用例，再检查触发、功能和性能。用英文metadata描述能力，中英文请求均可适用。
- [Anthropic：How we use skills](https://claude.dev/blog/lessons-from-building-claude-code-how-we-use-skills/)：真实Gotchas、API参考及可组合脚本承载重复工作；不重复Python常识或扩充每步检查制度。
- [OpenAI：Testing Agent Skills](https://developers.openai.com/blog/eval-skills)：分开成果、过程、表达和效率。离线脚本正确、metadata可见，与模型实际触发及Token收益分别评价。

frontmatter同时核对[Agent Skills规范](https://agentskills.io/specification)。name/description保留标准字段，环境要求放metadata.compatibility，兼容本机较早的quick_validate校验器。三个根文件连同metadata约234～259个英文词。正文、参考、脚本说明及默认提示统一为英文；中文用户请求、标题和数据字段仍受支持。

## 7. 未证实项及V7.9.2

- 英文metadata和具体脚本是否让模型主动读取并正确使用，仍需真实行为评测。英文内容也不保证跨模型收益一致。
- 例子只给可组合方法。业务公式、归属策略、投影适用性和路网建模仍需模型理解任务。
- 几何事实脚本按指定样本工作，平面XY不代表椭球/三维测量；顶点距离不能证明整条边界。CSV与大表内存开销仍由任务规模约束。
- 当前校验可以证明脚本结果、错误状态、索引和引用，不能证明图片审美或复杂未知任务正确率。较大数据、其他驱动和宿主安装仍需验收。
