# GIS-Agent V9.0.3 详细设计方案：分层异常信号、防停滞恢复、诚实拒答与 `gis-verification` 升级

- **版本定位**：V9.0.3（紧接 V9.0.2 提交 `7873369`，分支 `feature/v9`）
- **范围边界**：
  - **纳入本版**：运行时分层异常信号（Anomaly Signals）、确认即放行的一轮式核实门控（Acknowledge-Once Finish Gate）、执行防停滞与退避护栏（Loop & Stagnation Breaker）、低阻力诚实拒答/反问机制（Honest Abstention）、以及 `gis-verification` Skill 与配套轻量蜕变/不变量验证资产升级。
  - **明确延后**：`gis-cartography`（专题制图 Skill 与视觉复核系统）保留现状，留待 V9.0.4 单独重构，避免与校验内核耦合变更。
  - **零增重原则**：不恢复 V7.3–V7.6 的多 Agent 强制审核委派流程（[v7-postmortem-and-single-agent-plan.md](v7-postmortem-and-single-agent-plan.md) 已证实其导致轮次与成本翻倍），保持单 Agent、`inspect_fast` 轻量探针与稳定 KV Cache 前缀。

## 一、学术调研根基（CCF-A 顶会研究对标）

只靠提示词（Skill 文本）要求模型“仔细检查、诚实认错”，在理论与实证上均存在天花板。V9.0.3 的每项机制均对应以下顶会结论：

| 研究主题 | 代表顶会与文献 | 核心发现 | 对 V9.0.3 的直接设计约束 |
| :--- | :--- | :--- | :--- |
| **内在纠错失灵与工具外证** | **ICLR 2024** *Large Language Models Cannot Self-Correct Reasoning Yet* (Huang et al.); **ICLR 2024** *CRITIC* (Gou et al.) | 无外部反馈时，“再检查一遍”常因确认偏误把对改错；有效纠错依赖**生成 → 确定性工具客观取证 → 修正**闭环 | 不能靠提示让模型自我反思，必须依赖工具返回的客观数字体征与小样本断言证据 |
| **验证器误报与假阳性代价** | **NeurIPS / ICLR** *Verifier Gap*、*HALLMARK*、*Over-Refusal in Verifiers* | 部署成败往往取决于**假阳性率（FPR）**而非单纯召回；粗糙硬规则会误杀合法正常输出，逼迫模型绕过约束 | **采纳 Codex 关键修正**：`feature_count==0`、`crs==""`、`invalid_sample_count>0`、`valid_ratio==0.0` 仅作为**异常信号**而非通用失败判定 |
| **静默语义失败与蜕变检验** | **ICSE / FSE / ISSTA / PVLDB 2024–2026** *Agentic Property-Based Testing*、*GeMTest*、*Radar*、*Testora* | 程序 `returncode==0` 常掩盖“分子分母反了、丢多部件、DN 未定标”等静默错误；缺乏真值 Oracle 时需用**守恒与蜕变关系（MRs）** | `gis-verification` 升级为**“守恒不变量 + 蜕变抽样 + 最小反例对照”**，低成本戳破静默错误 |
| **死循环检测与策略切换** | **ICSE** *RepairAgent*、*InspectCoder*、**ICLR** *SAUP* | 遇到同类报错若无外力打断，模型会围绕局部语法/参数反复空转耗尽预算 | 运行时记录失败/异常签名与重复次数，达到阈值自动注入退避与切换策略提示 |
| **动作偏置与诚实拒答** | **NeurIPS 2026 Oral** *AgentAbstain*; **ETH SRI 2026** *Coding Agents Don't Know When to Act*; **ICML** *Clarification with Information Gain*; *KnowNo* | 前沿模型存在 **35%–65% 的 Action Bias**，即使缺数据或不可解仍强行“交付文件”；“解题”与“知止/认错”是解耦能力 | 非对称 `finish_task` 门控：降低 `blocked`/`needs_input` 阻力、零写入直接认错合法化，要求先查后写、不可知即上报 `UNKNOWN` |

## 二、总体架构：四层协同设计（机制层 + Skill 层）

```text
工具执行 (run_python_script / run_qgis_algorithm / inspect_data)
   │
   ├─► [1. 分层异常信号器 Anomaly Detector] —— 客观抽取 spatial / spatial_vitals 异常标记与级别，永不盲目重写脚本
   │
   ├─► [2. 防停滞循环监测 Stagnation Tracker] —— 连续同类报错/相同失败模式计数，触发纠偏或强制止损提示
   │
   ▼
模型决策 (继续修复 / 运行 gis-verification 性质验证 / 调用 finish_task)
   │
   ├─► [3A. 非对称终结门控: completed] —— 损坏/未修复末轮失败硬拦截；未确认异常信号触发「确认/修复一次门控」
   │
   └─► [3B. 非对称终结门控: blocked / needs_input / partial] —— 零阻力放行，保留已有阶段成果与清晰证据边界
```

## 三、模块级详细设计

### 模块 1：分层异常信号体系（`gis_agent/runtime/inspect_fast.py`）

严格遵循 **“指出异常（Surface Anomalies），不把症状当判决（No Universal Hard-Fail）”** 原则。在现有 `extract_vital_signs` 提取的客观字段基础上，新增纯确定性函数 `detect_spatial_anomalies(spatial: dict[str, Any]) -> list[dict[str, str]]`，附加到 `outputs[].anomalies` 与 `run_qgis_algorithm` 的 `anomalies` 字段中，并定义三级分层：

| 层级 | 触发编码 (`code`) | 客观触发条件 | 语义说明（不作业务定罪） | 门控默认行为 |
| :--- | :--- | :--- | :--- | :--- |
| **L1 提示级 (`notice`)** | `UNSCALED_HIGH_DN` | 栅格 `dtype` 为整型且 `raw_max > 100`、`scale == 1.0` | 若计算 SAVI/EVI 等非尺度不变指数需核对定标 | 随工具结果展示，**不拦截** |
| **L1 提示级 (`notice`)** | `PARTIAL_INVALID_GEOMETRY` | 矢量 `0 < invalid_sample_count < feature_count`（抽检存在部分无效几何） | 可能是原始输入固有自相交；若用于叠加/面积建议修复 | 若交付则触发一次确认提醒 |
| **L2 告警级 (`warning`)** | `ZERO_FEATURES` | 矢量 `feature_count == 0` | 可能是合理空筛选结果，也可能是坐标系错配导致空间连接全丢 | 未经确认或后续核查不得静默 `completed`；确认后放行 |
| **L2 告警级 (`warning`)** | `MISSING_CRS` | `crs == ""` | 可能是局部工程无投影数据，也可能是写出时丢失 CRS 定义 | 未经确认不得静默 `completed`；确认后放行 |
| **L2 告警级 (`warning`)** | `ALL_INVALID_OR_EMPTY` | `feature_count > 0` 且抽样全部为空或全部无效几何 | 输出几何全坏，极可能构建几何失败 | 未经确认不得静默 `completed`；确认后放行 |
| **L2 告警级 (`warning`)** | `ALL_NODATA_RASTER` | 栅格概览 `valid_ratio == 0.0` | 可能是边缘空白瓦片，也可能是错位裁剪导致整幅栅格全 NoData | 未经确认不得静默 `completed`；确认后放行 |
| **L2 告警级 (`warning`)** | `CONSTANT_RASTER_SURFACE` | 栅格有效像元>1且 `raw_min == raw_max`（且为浮点连续型） | 可能是平坦区，也可能是栅格计算式退化为常数值 | 未经确认不得静默 `completed` |
| **L3 致命级 (`fatal`)** | `CORRUPT_OR_UNREADABLE` | 空间文件后缀匹配且非空，但 `inspect_single` 读取直接抛异常 | 文件头损坏、未正常关闭（如 WAL 未落盘） | **硬拦截 `completed`**（仅允许修复或 `blocked`/`partial`） |

**兼容性保证**：
- `attach_spatial_vitals` 仅在检测到异常时才向产出条目新增轻量 `"anomalies": [{"level": "warning", "code": "ZERO_FEATURES", "message": "..."}]`，健康产出零额外 token。
- 对多输出脚本仅扫描前 3 个新产出的空间文件（维持 `<= 150ms` 预算），不影响大批量输出性能。

### 模块 2：确认即放行的非对称终结门控（`gis_agent/tools/planning.py` & `gis_agent/agent.py`）

解决两类核心矛盾：**静默错漏放过 `completed`** vs **严苛门控误杀正常特殊输出或阻碍诚实认错**。

#### 2.1 `finish_task` 参数温和扩展（保持 KV Cache 静态 Schema）
在 `finish_task` 工具定义中增加两个**可选**参数（旧调用 100% 兼容）：
- `acknowledged_anomalies: list[str] | None = None`：当最终交付文件存在 L1/L2 异常信号（如正常的空筛选 `ZERO_FEATURES`、局部坐标工程栅格 `MISSING_CRS`）时，模型通过列明对应异常编码或核实说明，显式声明“已查明为预期结果或已受限范围的输入固有问题”。
- `evidence: list[str] | None = None`：可选的简短关键取证结论摘要（如 `"area_diff=0.00%"`、`"missing_layer: landuse_2020"`），提升机器审计可读性与拒答可信度。

#### 2.2 非对称 `Agent.accept_finish` 状态机规则

1. **针对 `status == "completed"`（防静默失败 + 零永久误杀）**：
   - **硬拦截条件（Fatal Gate）**：
     - 原有检查：路径缺失/非绝对路径、0 字节文件、`plan.unfinished()` 非空、记忆未解决报错。
     - **新增 1（`CORRUPT_OR_UNREADABLE`）**：若任一交付 `artifacts` 在最近一次体征扫描中处于 `fatal` 损坏状态且后续无重新写出成功记录 → 拦截并要求修复或改状态。
     - **新增 2（最后执行未闭合失败）**：若与某 `artifact` 同路径或创建它/最后修改它的工具执行以 `ok=False` 失败，且此后无重新成功或显式说明 → 提示核实。
   - **确认一次门控（Acknowledge-Once Gate — 核心创新）**：
     - 收集当前本轮所有已交付 `artifacts` 的**最新有效执行产生的尚未被后续成功覆写覆盖的 L1/L2 异常信号**（`pending_anomalies`）。
     - 若存在异常信号，且既不在本次调用的 `acknowledged_anomalies` 中、模型此前也**未针对该文件路径运行过独立核查工具**（`summarize_fields`、`check_spatial_relation` 或针对该交付路径的 `inspect_data`）：
       - **首次拦截并返回提示**：`ok: False`，明确列出 `anomalies` 及具体文件名，提示模型：“*已检测到交付产物存在以上空间异常信号。若是脚本/坐标/过滤条件错误请修复；若经核实确为任务预期结果（如合法空交集）或原数据固有局限，请在 summary 写明局限并在 acknowledged_anomalies 中传入对应编码（或改用 partial/blocked）后再次提交 finish_task。*”
       - 模型二次调用 `finish_task(status="completed", acknowledged_anomalies=[...])` 时**无条件放行**，绝不制造死循环。

2. **针对 `status in {"blocked", "needs_input", "partial"}`（贯彻 *AgentAbstain* 反偏置）**：
   - **降阻放行**：
     - 即使模型在任务首轮仅调用 `inspect_data` / `list_files` 发现缺失关键图层或未定义字段、**从未创建 `update_plan`、也未执行任何 Python 脚本（`execution_started=False`）**，调用 `finish_task(status="blocked", reason="missing_input", summary=...)` 或 `needs_input` 时，**直接合法放行**。
     - 若此前已建有 `plan`，当模型诚实转入 `blocked` 或 `needs_input` 时，不把 `unfinished_plan` 当成报错阻止结束，仅将其透传为客观元数据 `"unfinished_plan"`（已有行为保持并强化文案友好性）。
     - 对 `blocked`/`partial` 允许 `artifacts=[]` 或仅保留已通过前期检查的部分有效阶段成果。

### 模块 3：执行防停滞与强制止损（`gis_agent/agent.py` Loop & Stagnation Breaker）

针对 **ICSE *RepairAgent* / 死循环研究**：在 `Agent` 单次交互运行中维护一个轻量的**进程内错误/停滞观测器**（也可同步精简存入 `RunState` 的可选轻量列表或从最近工具消息窗口即时统计，避免更改 SQLite Checkpointer 格式！）：

**零 Schema 迁移设计**：直接利用当前 `self.messages[state["turn_start"]:]` 中本轮已记录的 `tool` 与 `assistant` 批次即时统计即可，**天然支持断点 `resume` 恢复且 100% 兼容现有 SQLite 检查点**！

具体判定规则（从 `self.messages[state["turn_start"]:]` 末尾往前扫描连续失败工具批次）：
1. **错误签名归一化 `_failure_signature(tool_name, args, result)`**：
   - 对 `run_python_script`：提取 `(tool_name, script_name_or_hash, last_exception_line)`（例如 `KeyError` / `CRSError` / `ValueError`）。
   - 对 `run_qgis_algorithm`：提取 `(tool_name, algorithm_id, normalized_error)`。
   - 对其他工具：提取 `(tool_name, error_prefix)`。
2. **两档渐进干预（写入尾部动态 `business["stagnation_alert"]`，不破坏前缀 KV Cache！）**：
   - **第 1 档（同类错误连续失败 >= 2 次，或本轮连续失败总数 >= 3 次）**：
     在动态尾部 `business` 注入：
     ```json
     {
       "stagnation_alert": {
         "level": "warn",
         "consecutive_failures": 2,
         "repeated_signature": "run_python_script:CRSError",
         "advice": "同一错误连续出现，请停止微调重跑；先用 inspect_data/summarize_fields 或极小样本探针核实输入，或读取对应 Skill 参考文档切换实现路线。"
       }
     }
     ```
   - **第 2 档（连续失败达 >= 5 次，含未解决的同类反复异常产出）**：
     注入 `"level": "escalate"`：明确指出能力/方法或数据前提可能已达当前边界，要求**下一轮必须二选一**：要么切换到完全不同的底层引擎/已验证资产，要么立即调用 `finish_task(status="blocked"|"needs_input"|"partial")` 诚实上报实际阻碍与已完成部分，停止空耗预算。

### 模块 4：Prompt 对齐与 `gis-verification` 深度重构

#### 4.1 `gis_agent/prompts/system.j2` 微调（增加 2 句反 Action Bias 核心指令）
- 强调**先探后算、事实先行**：“修改或写入前先通过工具或体征核对文件结构与 CRS；遇到缺失数据、冲突需求或多次失败无法可靠修复时，**诚实调用 `finish_task(status="blocked"|"needs_input"|"partial")` 是完全受鼓励的正当交付**，严禁靠编造参数、臆测坐标系或无依据近似强行 `completed`。”

#### 4.2 `gis_agent/skills/gis-verification/` 深度重构（对齐 CCF-A 性质/蜕变检验规范）
针对 [v81-exam13-diagnostic-review.md](v81-exam13-diagnostic-review.md) 暴露的“老版 `gis-verification` 触发率低、缺乏可复制性质验证模板”问题，对标 Anthropic / OpenAI Skill 规范做彻底升级（保留现有已验证资产并补全短板）：

1. **清晰的 `SKILL.md` 路由表（`<= 115` 行，纯英文）**：
   - Frontmatter `description` 明确区分触发时刻：**When to use**（任何多步分析交付前、指标/公式/连接/选址/插值后出现异常体征 `outputs[].anomalies`、边界结果不确定或计划报告 `blocked`/`partial` 时）；**Skip when**（仅读取单个元信息、单步原子工具已由体征直接证实）。
   - 核心方法论固定为 **4 类高性价比外部取证原语（Minimal Extrinsic Evidence）**：
     1. **Conservation & Ledger Audits（守恒与台账核对）**：保留并衔接 [identity_audit.py](../gis_agent/skills/gis-verification/scripts/identity_audit.py) 与 [allocation_balance.py](../gis_agent/skills/gis-verification/scripts/allocation_balance.py)。
     2. **Metamorphic & Scaling Invariance（无真值蜕变与量纲不变性验证）**：新增可运行脚本 `gis_agent/skills/gis-verification/scripts/metamorphic_checks.py`，封装以下可在 `< 1s` 内直接导入执行的轻量函数：
        - `check_conservation(expected_total, observed_total, unmatched_total=0.0, rtol=1e-6)`
        - `check_permutation_invariance(fn, df)`（打乱输入行序后按稳定业务键排序比较结果，捕捉隐含行号索引/FID 写回 Bug）
        - `check_scale_sensitivity(value_fn, scaled_fn)`（检验公式对尺度缩放的敏感性，暴露未定标 SAVI / 单位混用问题）
        - `compare_boundary_predicates(pts_gdf, polys_gdf)`（对照 `intersects` vs `within` vs `covered_by` 差异计数，瞬间定位边界点归属漏洞）
     3. **Small-Sample Exact Oracle Cross-Check（小样本精确 Oracle 对照）**：针对大型计算，抽样 `k = 10..20` 个关键对象用暴力精确法 / 不同库对照（例如 `MultiDiGraph` 最短路 vs 矩阵实现、小网格人工算子 vs 栅格脚本、`k=5` 个样本人工点查栅格像元值），**绝不为了验证把全量重跑一遍**。
     4. **Abstention & Limitation Matrix（承认错误与 `UNKNOWN` 决策表）**：给模型明确的操作口诀，定义何时允许 `completed`（带 `acknowledged_anomalies` + 局限说明）vs 必须用 `partial` vs 必须用 `needs_input` vs 必须立即 `blocked`。

2. **保留并精炼现有资产**：
   - 原有 [geometry_facts.py](../gis_agent/skills/gis-verification/scripts/geometry_facts.py)、[precision_example.py](../gis_agent/skills/gis-verification/scripts/precision_example.py)、[validation_split.py](../gis_agent/skills/gis-verification/scripts/validation_split.py)、[checks.md](../gis_agent/skills/gis-verification/references/checks.md) 全部保留其既有接口与回归兼容测试；仅按新结构梳理 `SKILL.md`、`checks.md` 与 `references/abstention-and-metamorphic.md`（并保持与 V9.0.2 5 个空间分析新 Skill 的精确单跳链接）。

## 四、实施拆分与验证计划（0 收费模型调用离线闭环）

| 阶段 | 核心变更文件 | 离线验证标准 |
| :--- | :--- | :--- |
