# V8 候选需求

状态：仅记录候选。V7 收官不实施。后续从冻结的 V7 基线逐项选择。

| 候选 | 解决的问题 | 最小验收方向 |
| --- | --- | --- |
| 工作流树与局部重算 | 修正一处后重复执行昂贵上游；缓存依赖不明确 | 明确步骤输入、参数和输出指纹；只重算受影响下游，保留原分支。先用一条小流程验证。 |
| 主动质疑 | 模型方法可执行，关键语义仍可能错误 | 在少量高影响假设处寻找反例；观察检错率、误报和额外成本。保留模型自由决策。 |
| 人工介入 | 专业歧义和不可靠配准需要用户判断 | 提供当前证据、问题和选择；记录人工决定，避免隐含业务指导。 |
| 暂停与恢复 | 原生长作业阻塞；取消后执行状态可能不确定 | 区分未启动、运行中、失败和完成；提供可控取消与持久状态，不自动重复未知写入。 |

这些能力需要先明确外部文件、副作用和恢复边界。现有 LangGraph 检查点不能直接证明外部作业或文件已经安全完成。

历史[工作树草案](v8.0-workflow-tree.md)基于 V7.6，含旧接口。它用于讨论；实现前必须按 V7 冻结源码重新核对。暂不引入新子 Agent、大型规则系统或新的评测平台。

优先用小型离线反例定位机制，再经用户授权做少量真实任务。V7.9.3 与 V7.9.2 的题目、数据规模不同，不能用两次总费用直接评价机制收益。
