# GIS-Agent V9.0.1：双环底座边界收口、三端挂载契约与实测细节修正设计

- **文档版本**：V9.0.1（实施定稿）
- **基准分支与提交**：`feature/v9`（基于 `0139d8f`）
- **设计目标**：在不引入任何重型前端框架、不破坏现有 114 项离线测试与会话完整性的前提下，消除 V9.0 核心底座向三端外壳（独立桌面工作台、QGIS 原生插件、Claude Code / Codex 外部 Harness）绑定时的 4 处耦合缝隙，并同步落地“方案 A”9 题线上实测暴露的 2 处执行与知识库微调。

---

## 一、双环底座架构定界（Design Rationale）

V9.0 已完成“静态工具协议 + 快速头信息探针 + 零 `langgraph`/`tokenizers` 纯标准库状态机”改造。为使后续三条终局路线均只需编写 100～300 行纯胶水层即可挂载，底座内部按依赖方向严格划分为两层同心环：

1. **内环（Ring 1：确定性地理原语与领域知识包）**
   - **组成模块**：`gis_agent/runtime/{paths.py, runner.py, inspect_fast.py, probe.py}`、`gis_agent/integrations/{qgis, plotting}`、`gis_agent/tools/{qgis_alg.py, qgis_python.py, builtin.py}`、`gis_agent/skills/`。
   - **硬约束**：不依赖大模型客户端、不依赖 `SessionStore` 或检查点状态机、不依赖任何 GUI 组件。
   - **直接消费者**：**路线三（Harness MCP 插件端）** 直接绑定内环，向 Claude Code / Codex / Cursor 暴露静态确定性 GIS 工具与 3 套专业 Skills，避免双层 Agent 循环套娃。

2. **外环（Ring 2：无头会话引擎与事件流）**
   - **组成模块**：在内环之上叠加 `gis_agent/core/{loop.py, context.py, planning.py, memory.py, events.py}`、`gis_agent/persistence/{sessions.py, checkpoints.py, executions.py, interaction.py}`、`gis_agent/{agent.py, application.py}`。
   - **硬约束**：不导入 `PyQt` / Web 框架、不直接使用终端 `input()` / `print()`；所有外部交互仅通过**显式配置参数、`WorkspaceContext` 上下文快照、`EventCallback` 实时事件回调与线程安全 `cancel_event` 中断信号**完成。
   - **直接消费者**：**路线一（独立桌面 EXE 工作台）** 与 **路线二（QGIS 停靠面板插件）** 绑定外环，在后台工作线程驱动 `Conversation` 并通过事件流刷新主线程地图画布。

## 二、V9.0.1 四项实施模块详细设计

### 模块 1：统一包路径与导入根定位（消除源码目录层级硬编码）

#### 1.1 现状问题
`gis_agent/runtime/probe.py:63` 与 `gis_agent/tools/qgis_python.py:48-190` 多处使用 `Path(__file__).resolve().parents[1]` 或 `parents[2]` 推导 `GIS_AGENT_PROJECT_ROOT` 及内部脚本路径。当代码安装到 `uv` 虚拟环境的 `site-packages`、QGIS 的 `plugins/<name>/` 目录或 PyInstaller 冻结目录（`sys._MEIPASS`）时，`parents[2]` 不再指向正确的导入根或工作目录。

#### 1.2 设计方案
新增 `gis_agent/runtime/paths.py`，提供三个零副作用纯函数：
- `package_dir() -> Path`：返回 `gis_agent` 包根目录（`Path(__file__).resolve().parents[1]`）。
- `import_root() -> Path`：若处于 PyInstaller 冻结态（`getattr(sys, "_MEIPASS", None)` 存在且其下含 `gis_agent`），返回 `Path(sys._MEIPASS).resolve()`；否则返回 `package_dir().parent`。该目录即为子进程 `PYTHONPATH` / `GIS_AGENT_PROJECT_ROOT` 所需的精确父目录，保证无论源码开发、wheel 安装还是插件目录部署，子进程均可 `import gis_agent.integrations.plotting.runtime`。
- `package_resource(*parts: str) -> Path`：返回 `package_dir().joinpath(*parts)`，统一替代各工具模块中手工拼接的 `parents[1] / "integrations/..."` 与 `parents[1] / "runtime/..."`。

同时调整 `gis_agent/cli.py`：当 `gis_agent` 位于 `site-packages` 等非仓库目录时，默认 `--project` 自动回退至 `Path.cwd()`；在源码仓库下运行时保持仓库根目录兼容。

### 模块 2：线程安全主动中止（`cancel_event`）与外环统一入口敞开

#### 2.1 现状问题
1. `application.py::open_conversation(config, session_id)` 未透传 `api_key`、`on_event`、`extra_tools`、`workspace_context`、`allowed_write_roots`、`protected_paths`，且在缺失环境变量时直接抛出原生 `KeyError`。
2. CLI 用户可用 `Ctrl+C` 终止整个进程，但桌面端与 QGIS 插件与宿主共享生命周期，用户在 UI 点击“停止运行”时**绝不能杀死宿主进程**，必须通过协作式 `threading.Event` 在 `<= 0.2s` 内回收正在运行的子进程树，且**保证 `SessionStore` 消息配对完整性（`message_units` 不损坏）与 SQLite 检查点闭合（`next == ()`）**。
3. `tool_finished` 事件目前仅携带 `ok` 与 `elapsed_ms`，未携带本次工具新产出的文件列表 `outputs`，导致前端画布无法直接从事件流获取待渲染图层路径。

#### 2.2 子进程树协作式中断契约（`gis_agent/runtime/runner.py` & `integrations/qgis/client.py`）
1. `run_process(..., cancel_event: threading.Event | None = None)`：
   - 将单次阻塞 `process.wait(timeout=timeout_sec)` 改为固定步长轮询循环（每次等待 `min(0.2, deadline - perf_counter())`）：
     - 若 `cancel_event is not None and cancel_event.is_set()`：立即调用 `terminate_process_tree(process)`，标记 `cancelled = True`、`returncode = -2`、`status = "cancelled"`；
     - 若到达 `deadline`：保持原超时逻辑（`timed_out = True`、`terminate_process_tree(process)`、`returncode = -1`、`status = "timed_out"`）。
   - 返回字典新增布尔字段 `"cancelled": cancelled`。
2. `run_python_script`、`make_qgis_python_tools`、`QGISClient.run_json`、`make_run_qgis_tool` 均透传可选 `cancel_event: threading.Event | None = None`：
   - 当 `outcome["cancelled"]` 为真时，返回 `{"ok": False, "status": "cancelled", "cancelled": True, "error": "执行已被用户主动中止，子进程树已清理。", ...}`。

#### 2.3 Agent 状态机中止闭合契约（`gis_agent/agent.py`）
为严守 `SessionStore` 的 `assistant(tool_calls) -> tool * N` 原子批次不变量（绝不留下半截悬空 `tool_calls` 导致会话损坏）：
1. `Agent` 新增可选字段 `cancel_event: threading.Event | None = None` 与 `workspace_context: dict[str, Any] | None = None`。
2. **模型请求前检查（`Agent.model`）**：
   - 若 `self.workspace_context` 非空，将其并入末尾动态 `business["workspace_context"]`（不改历史前缀，不破坏 KV Cache）。
   - 调用 `self.chat(...)` 前检查 `self.cancel_event and self.cancel_event.is_set()`：若已置位，不发送网络请求，直接返回 `{"outcome": {"ok": True, "status": "cancelled", "summary": "任务已由用户主动中止，已完成阶段的产物已保留。"}, "record_hash": self.record_hash()}`，随后由 `AgentLoopRunner` 自然进入 `finish()` 落盘闭合。
3. **工具批次内检查（`Agent.tools`）**：
   - 遍历 `calls` 时，若在启动某个调用前已检测到 `self.cancel_event.is_set()`，则**不再启动后续真实工具**，直接为该 `call_id` 生成标准工具消息 `{"ok": False, "status": "cancelled", "cancelled": True, "error": "任务已中止，该调用未启动。"}`，确保本批全部 `tool_call_id` 均有合法闭合消息。
   - 当本批 `calls` 闭合落盘完毕后，若 `self.cancel_event and self.cancel_event.is_set()`，在 `state` 上写入 `state["outcome"] = {"ok": True, "status": "cancelled", "summary": "任务已由用户主动中止，子进程树已清理，已完成阶段的产物已保留。"}`。`AgentLoopRunner` 检测到 `state["outcome"] is not None`，不再发起下一轮模型调用，直接跳转 `finish()` 写入最终说明、置 `next = ()` 并广播 `turn_finished(status="cancelled")`。
4. **事件流增强**：`tool_finished` 事件额外附带 `outputs=result.get("outputs", [])`（当 `result` 为含 `outputs` 的字典时），供桌面端与 QGIS 插件直接订阅新生成的图层文件。

#### 2.4 会话门面扩展（`gis_agent/application.py`）
1. `Conversation` 新增：
   - `cancel_event: threading.Event = field(default_factory=threading.Event)`
   - `workspace_context: WorkspaceContext | None = None`
   - `request_stop() -> None`：置位 `self.cancel_event.set()`（供 GUI 线程随时安全调用以中断后台正在运行的 `send()` / `resume()`）。
   - 在每次新发起 `send()` / `reply()` / `continue_answer()` / `resume()` 前自动清理上一轮残留的 `self.cancel_event.clear()`（除非调用方显式保持）。
2. `open_conversation(...)` 扩展签名（向后完全兼容旧调用）：
   ```python
   @contextmanager
   def open_conversation(
       config: AppConfig,
       session_id: str,
       *,
       api_key: str | None = None,
       on_event: EventCallback | None = None,
       extra_tools: list[Tool] | None = None,
       workspace_context: WorkspaceContext | None = None,
       allowed_write_roots: tuple[Path, ...] = (),
       protected_paths: tuple[Path, ...] = (),
       cancel_event: Event | None = None,
   ) -> Iterator[Conversation]:
   ```
   - `resolved_key = api_key or os.environ.get(config.api_key_env)`；若为空则抛出清晰中文 `ValueError(f"未提供模型密钥，请传入 api_key 或设置环境变量 {config.api_key_env}。")`。

### 模块 3：路线三标准 STDIO MCP Server 落地（`gis_agent/adapters/harness_mcp.py`）

#### 3.1 设计目标
无需引入第三方重型依赖，使用纯 Python 标准库实现符合 **Model Context Protocol (JSON-RPC 2.0 over STDIO)** 规范的服务端，使 Claude Code、Codex CLI、Cursor 可直接通过一条配置命令挂载 GIS-Agent 的内环工具与专业 Skills。

#### 3.2 协议与工具面设计
1. **传输帧兼容**：
   - 标准 MCP 2024-11-05 / 2025-03-26 STDIO 采用按行分隔的 UTF-8 JSON-RPC 消息（同时兼容识别 `Content-Length:` 头部帧并按相同帧格式回包），并将所有调试/运行日志严格重定向至 `sys.stderr`，确保 `sys.stdout` 仅输出纯净协议帧。
2. **暴露工具集（`build_harness_tools`）**：
   - `probe_gis_environment`：返回 GIS Python 解释器、GDAL/QGIS 状态与空间库版本清单；
   - `inspect_data`：毫秒级矢量/栅格头信息、物理量纲与 `256×256` 概览抽样；
   - `summarize_fields`：属性空值、唯一键与数值分布；
   - `check_spatial_relation`：CRS 一致性与空间拓扑关系核查；
   - `list_gis_skills`（**新增**）：返回内置 3 套专业 Skills（`gis-spatial-analysis`、`gis-verification`、`gis-cartography`）的名称、适用场景摘要与本地 `SKILL.md` 绝对路径，引导外部 Coding Agent 按需读取参考规范与绘图运行时；
   - `search_qgis_tools` & `run_qgis_algorithm`（当本机配置了可用 QGIS 时自动挂载）。
3. **支持方法**：
   - `initialize`：返回协议版本、`capabilities: {"tools": {}}` 与 `serverInfo`；
   - `notifications/initialized`（及其他无 `id` 通知）：静默确认，不回冗余错误；
   - `ping`：返回 `{}`；
   - `tools/list`：将 `Tool.parameters` 映射为 MCP 标准字段 `inputSchema`；
   - `tools/call`：执行目标工具，返回 `{"content": [{"type": "text", "text": json_text(result)}], "isError": ...}`；未知工具或参数异常返回标准结构化错误而不中断服务进程。
4. **启动入口**：
   - 支持 `python -m gis_agent.adapters.harness_mcp [--project <dir>]`；
   - 在 `pyproject.toml` 的 `[project.scripts]` 注册 `gis-agent-mcp = "gis_agent.adapters.harness_mcp:main"`。

### 模块 4：线上实测（方案 A）反馈的两项精准收口

#### 4.1 收紧 `run_python_script` 单次超时边界（`gis_agent/tools/qgis_python.py`）
- **背景**：方案 A 第 `09` 题中，模型首轮对 7.1 万公里路网调用全网合并缓冲时主动传入 `timeout_sec=900`，耗尽了 30 分钟总墙钟的一半；超时回收后改写的 56 瓦片分块脚本仅用 561 秒即算完真值，却因前段耗时过多差几秒未导出最终 CSV。
- **修改**：
  - 默认 `timeout_sec` 由 `300` 调整为 `180` 秒（3 分钟足以跑完常规分析与单瓦片测速，卡死时更早触发回执推动模型分治）；
  - 允许显式传入的范围由 `5..3600` 收紧为 `5..600` 秒（单次上限 10 分钟），并在工具 Schema 描述中明确注明：“默认 180 秒，范围 5～600 秒；耗时更长的大规模空间计算请先抽样测速并按瓦片/阶段拆分持久化。”

#### 4.2 补充非尺度不变光谱指数定标与量纲提示（`gis_agent/skills/gis-spatial-analysis/references/terrain-imagery.md`）
- **背景**：方案 A 第 `32` 题（SAVI 冰雹植被损失）轮次下降 38%、成本下降 41%，但因原影像缺失 `scale` 标签（`scale=1.0`，像元值处于千量级整数 DN），模型将未缩放 DN 直接代入含加性常数 `L=0.5` 的 SAVI 分母 `NIR + Red + L`，导致土壤调节项在千量级下退化失效。
- **修改**（严格遵守全英文、无中文字符、相对链接有效的 Skill 规范）：
  - 在 `terrain-imagery.md` 新增短小节 `## Radiometric scaling and non-scale-invariant indices`：
    - 指出含无量纲加性常数的光谱指数（如 SAVI、EVI，其中 `L = 0.5` 定义在 `[0, 1]` 地表反射率域）不具备乘法尺度不变性：在 `0..10000` 未缩放整数 DN 上直接加 `0.5` 会使土壤调节项失效并改变数值量级；
    - 要求计算前先通过 `inspect_data` 核对 `dtype`、`scale`/`offset` 与概览值域（`raw_min`、`raw_max`）：若存在传感器缩放系数则先转为物理反射率；若影像呈典型 `0..10000` 定点反射率量级但缺失元数据标签，不得静默当作 `[0, 1]` 反射率计算加性指数，应检验/对比 `DN / 10000` 反射率折算并如实披露定标假设。

## 四、离线验收标准（Acceptance Criteria）

1. **包路径测试**：模拟非仓库工作目录与冻结目录（`monkeypatch` `_MEIPASS`），验证 `import_root()` 与 `package_resource()` 解析准确。
2. **UI/插件运行中主动停止测试**：在后台线程启动真实耗时子进程（如 `time.sleep(30)` 的 Python 脚本），主线程 `0.3s` 后调用 `conversation.request_stop()`：
   - 断言总耗时 `< 3.0s` 返回 `status == "cancelled"`，子进程树已被彻底清理；
   - 断言 `SessionStore.load()`（含 `message_units` 严格校验）零报错通过，SQLite 检查点 `next == ()`，且同一 `Conversation` 紧接着可继续正常发送下一轮新请求！
3. **`open_conversation` 外环契约测试**：无需设置系统环境变量，显式传入 `api_key`、`on_event`、`workspace_context` 与自定义 `extra_tools`，验证事件序列（含 `tool_finished` 中的 `outputs`）与工作区上下文注入完整生效。
4. **STDIO MCP 真机协议测试**：通过 `subprocess.Popen([sys.executable, "-m", "gis_agent.adapters.harness_mcp", ...])` 拉起真实独立 MCP 进程，经 `stdin`/`stdout` 完成 `initialize` -> `notifications/initialized` -> `tools/list` -> `tools/call`（`list_gis_skills`、`probe_gis_environment`、`inspect_data`）全链路往返核验。
5. **全量回归**：全仓库 `pytest tests benchmarks/geoagentbench/test_runner.py -k "not live"`（含 `test_v7911_skills.py` 语言与链接审计）100% 通过。
